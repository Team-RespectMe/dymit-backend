## TASK-70 auth/member 도메인 리팩토링
**STATUS** Done
**BACKGROUND**

현재 코드를 모듈로 모노리스 구조 형식으로 변경하려고 합니다.
인증과 회원 도메인을 최상위 디렉터리에 각각 도메인 명으로 된 패키지를 만들고
연관된 패키지들을 옮기고 테스트 코드까지 모두 리팩토링을 해주시길 바랍니다.

현재 패키지 구조는 패키지 최상단에
- adapters 어댑터 구현체 집합
- application 유즈케이스 및 포트 정의 집합
- common 공통 모듈
- configs 공통 컨픽
- controllers: Api 정의 및 Controller 집합
- domain: 도메인 모델 정의 집합
- ports: 포트 정의부
등으로 각 패키지 내부에 도메인 별로 패키지가 있고 거기에 정의가 되어있습니다

구조를 [PROJECT_STRUCTURE.md](.agent-dev/PROJECT_STRUCTURE.md)를 참고하여 
member 모듈과
auth 모듈을 정의해야 합니다.
논리적으로만 모듈로 모노리스를 사용할 것이므로 별도의 의존성 추가 등은 하지 마십시오.

**REQUIREMENTS**
- member/auth 관련 API의 인터페이스는 절대 수정되어선 안되며 동작 역시 수정되어선 안됩니다.
- JWTService 와 같은 부분은 공통 모듈로 분리하는게 좋겠습니다
- 컨트롤러에 인증 정보를 받는 어노테이션이 존재합니다 @LoginMember 와 같은 어노테이션인데 이 부분도 공통 모듈로 분리하고 
  from 메서드 등에 특정 패키지의 클래스를 요구하는 방식이라면 of 방식으로 수정하여 데이터를 직접 입력하는 방식으로 변경하십시오. 
- 수정 후 다른 패키지에 문제가 생긴다면 사용자 인터페이스가 변경되지 않는 선에서 수정은 허용합니다.
